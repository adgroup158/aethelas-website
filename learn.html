Overview

✦ All things verifiable AI memory education

Aethelas is a trust layer for AI memory — an infrastructure that makes AI verifiable, auditable, and provably forgettable on demand. It wraps any AI model with a cryptographic ledger, ensuring that everything the model learns, remembers, proves, or unlearns is recorded and verifiable.

Why it matters: Most AI systems are "black boxes" — you can't prove what they learned, when they learned it, or how to remove specific data. Aethelas solves this by making AI memory transparent and auditable.

Aethelas is built on four core operations: Learn, Remember, Prove, and Unlearn. These operations work together to create a complete, verifiable memory system for any AI.

What is Aethelas?

✦ Understand what makes Aethelas special

Aethelas is a verifiable AI memory infrastructure — not a foundation model, not general intelligence, and not a recursively self-improving system. It is a trust layer that can be wrapped around any AI model to make its memory verifiable, auditable, and provably forgettable.

Think of Aethelas as an immutable audit trail for AI memory. Every training event, every decision, and every memory operation is recorded on a cryptographic ledger. This means you can always prove:

  • What data the model learned
  • When it learned it
  • What the model knew at any past point
  • That specific data was deleted on request
💡 Aethelas in one sentence: A trust layer that provides verified, auditable, provably-forgettable memory around any AI.

In testing, Aethelas achieved 89.5% overall on its internal benchmark suite, with perfect scores on hallucination detection, mathematical correctness, value alignment, planning, and trust calibration.

How Aethelas Works

✦ The technology behind verifiable AI memory

Aethelas works by wrapping AI models with a cryptographic ledger that records every training event and decision. Here's how each component works:

1. The Ledger (Aethelas L1)

At the heart of Aethelas is a Rust-implemented Layer-1 blockchain with iPoS consensus (~5s block times, WASM VM, 20+ active nodes). Every transaction carries an AIDecision record, and the AI decision process is embedded directly into transaction validation.

2. The Continual Learning Module

The on-chain neural network uses a 7-16-8-1 architecture (273 trainable parameters), trained online via stochastic gradient descent as transactions arrive.

3. The Knowledge Engine

Genesis-seeded domain knowledge is stored as versioned, keyword-searchable entries. Every factual claim in a response traces to a specific, versioned knowledge entry rather than being generated freely.

4. The Verification Fence

A guardrail that sits between any LLM and the user. Every factual claim must cite a specific memory entry, and the fence checks citations, numeric accuracy, and coverage. Performance: Precision 1.00, Recall 0.929, F1 0.963.

5. Decentralized Storage with Provable Deletion

Each file is erasure-coded into n fragments, recoverable from any k. The on-chain commitment is a Merkle root over fragment hashes. Deletion proof: post-deletion challenge confirms zero fragments survive, and the root hash change provides tamper-evident proof.

🔒 Trust through cryptography: Every operation — learn, remember, prove, unlearn — is recorded on the ledger with cryptographic guarantees, making the system auditable without trusting any single party.

The Four Operations of Aethelas

✦ Learn, Remember, Prove, Unlearn

🧬 Learn

New training examples are appended to the ledger as they are encountered. The model trains continuously as new data arrives — without full retraining. This enables lifelong learning without the cost of retraining from scratch.

🧠 Remember

Past examples are replayed from the ledger during ongoing training to resist catastrophic forgetting. In tests, unbounded ledger replay reached 98.6–100.0% retention across sequential tasks.

🔮 Prove

The model's parameter state at any past point can be verified against a cryptographic commitment recorded at that point. The proof consists of: original weights hash, new weights hash, and a Merkle root over the replayed event set.

🌀 Unlearn

Specific data can be removed by rolling back to the state before it was learned and replaying the remaining history excluding it. In testing, removing one contributor's data: changed the storage root hash (cryptographic evidence), removed 100% of that contributor's entries, and left other contributors' data intact.

💡 The insight: Forgetting-resistance and unlearning are not separate mechanisms — they are the same replay operation run forward (include everything) or with an exclusion set (omit specific examples).

Rust-Implemented Layer-1 Blockchain

Aethelas L1 is built in Rust for performance and safety. It uses iPoS (intelligent Proof of Stake) where validator voting power is weighted by an AI-derived reliability score.

Continual Neural Network

The on-chain neural network uses a 7-16-8-1 architecture with 273 trainable parameters, trained online via stochastic gradient descent. The weights hash serves as a content fingerprint for verification.

Cryptographic Proof Layer

  • SHA-256 commitments — over transactions, decisions, and rules
  • Ed25519 signatures — for authentication and non-repudiation
  • Merkle roots — for compact, verifiable commitment to data sets

Aethelas L1 Network

✦ Understand what the Aethelas network is

Aethelas L1 is the Layer-1 blockchain that powers the Aethelas ecosystem. It is a Rust-implemented, BFT consensus network where AI-driven decisions are embedded directly into transaction validation and consensus.

  • Consensus: iPoS (intelligent Proof of Stake) — validator voting power weighted by AI-derived reliability score
  • Block time: ~5 seconds
  • Nodes: 20 active nodes running on real infrastructure
  • Smart contracts: WASM VM execution
  • Security: 18/18 red-team attacks blocked
🔗 Live network: Aethelas L1 is running on a public test network with 20 active nodes. The chain is live and transactionally active.

Aethelas Token (AETHL)

✦ Understand Aethelas's native token

AETHL is the native cryptocurrency of the Aethelas network. It serves as the economic backbone of the ecosystem, enabling:

  • Validator staking — AETHL holders can stake tokens to become validators or delegate to existing validators
  • Transaction fees — AETHL is used to pay for all network operations
  • AI decision verification — Verifying AI decisions requires a small AETHL fee
  • Storage payments — Decentralized storage costs are paid in AETHL
  • Governance — AETHL holders can participate in network governance

The token economics are designed to align incentives across validators, developers, and users — ensuring the network remains secure, decentralized, and efficient.
