Class-Incremental Learning: Where Naive Replay Fails

August 25, 2026 7 min read Akash Deep

Technical Reports 1 and 2 found that unbounded ledger-based replay outperforms bounded or absent replay on task-incremental continual learning. That's the easier setting: the model is told which task it's being evaluated on.

Today's report — TR-03 — tests the harder, more realistic setting: class-incremental learning. Here, a single shared classifier must correctly categorize among all classes introduced so far, with no task information at evaluation time.

⚠️ The result is negative: None of the three replay conditions — including unbounded ledger replay — prevents severe accuracy collapse. All three conditions fall to 9.4–19.4% final accuracy, only marginally above the 10% chance level for ten classes.

Why This Test Matters

Class-incremental learning is widely considered the hardest scenario in continual learning. A method that only succeeds in task-incremental settings has narrower practical value than one that also succeeds here. This test is a necessary honesty check on our earlier, more optimistic results.

Task-incremental learning is the easier setting: the model is told which task it is being evaluated on, and only needs to distinguish between a small number of classes within that task. Class-incremental learning requires the model to distinguish among all classes learned so far using a single shared output layer.

The Experiment

We used the same 8×8 grayscale digit image dataset as TR-02, extended to a 10-class problem introduced two classes at a time across five sequential tasks:

  • Task 1: classes (0, 1)
  • Task 2: classes (2, 3)
  • Task 3: classes (4, 5)
  • Task 4: classes (6, 7)
  • Task 5: classes (8, 9)

The network was extended to a 10-unit softmax output layer trained with cross-entropy loss, evaluated after each task on a cumulative test set containing all classes introduced so far — the standard protocol for measuring class-incremental forgetting.

The same three replay conditions were tested:

  • No replay — no memory at all
  • Bounded RAM — 50-example buffer, random eviction
  • Unbounded ledger — full history retained, 3 examples per step

The Results

After training on all five tasks sequentially, the final accuracy on the cumulative 10-class test set was:

Condition Final 10-class accuracy Chance level
No replay 9.4% 10%
Bounded RAM (n=50) 12.8%
Unbounded ledger 19.4%

All three conditions collapsed to near-chance performance. The chance level for 10 classes is 10%, so unbounded ledger replay — which dominated in the task-incremental setting — offered only a modest and practically meaningless improvement.

"Unbounded ledger replay does not solve class-incremental learning in its current, naive implementation."

Why It Fails

The failure mode is consistent with a known theoretical result in continual learning: replay-based methods that sample uniformly from memory without class-balancing or task-specific output heads suffer from severe bias toward recently seen classes.

As the number of classes grows, the shared classifier's decision boundary is increasingly dominated by the most recent classes, and earlier classes are effectively forgotten — even when replayed.

Unbounded ledger replay retains the data, but the naive sampling strategy (3 examples per step, uniformly at random) doesn't ensure a balanced signal across all classes. This is a structural limitation of the replay mechanism itself, not a failure of memory capacity.

A Methods Note — Full Reproducibility

In the interest of full reproducibility, we should note: an initial implementation of the softmax output layer exhibited numerical overflow (unbounded logits causing floating-point overflow in the exponential function), which produced a degenerate all-conditions-near-chance result on the first run.

We identified this as a numerical stability bug — not a finding about the architecture — and corrected it with logit clipping and gradient clipping before the run reported above. We flag this explicitly because without additional mechanisms such as output masking, class-balanced replay sampling, or per-class output isolation, naive replay is known to be insufficient in this setting.

Our result is a specific, measured instance of that general difficulty as it applies to the ledger-replay architecture, not a novel discovery of the difficulty itself.

What This Means for Aethelas

This result narrows the honest scope of applicability for the current implementation:

  • Well suited: Binary or few-way, task-segmented decisions — fraud detection, loan approval, compliance flagging — evaluated one decision type at a time
  • Not suited: A single model performing open-ended multi-category classification across many learned categories simultaneously

We consider this an important scope boundary to state plainly rather than discover in front of a customer or reviewer.

Limitations and Future Work

  • Single seed, single dataset, single architecture size
  • We did not test class-balanced replay sampling, output masking, or per-task output heads — any of which might substantially improve the class-incremental result
  • We also did not compare against established class-incremental methods (e.g., iCaRL, or regularization-based approaches) which are designed specifically for this harder setting

Conclusion

Unbounded ledger replay does not solve class-incremental learning in its current, naive implementation. We report this as a genuine limitation rather than omit it, consistent with our commitment to reporting what experiments actually show.

The architecture's demonstrated strength remains task-incremental, binary or few-way decision settings — which happens to describe the primary target application (fraud and compliance decisions) accurately.
